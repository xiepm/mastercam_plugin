| 发现 | 处理与验证 |
|---|---|
| 预览重建变化后旧计划仍可能再次执行 | 1.0.2 适配层使用不可变批准预览；候选在临时对象中构建，通过比较后才接入执行委托。重建或比较失败将计划标记 Invalidated，清空写入委托。实际生产 PreviewGuard 源码通过 5 项回归：变化、第二次尝试、构建失败、序列化失败、匹配成功。没有声称在 SDK 中诱发了预览漂移。 |
| 布尔值和数字被自动转换 | Pydantic 全局 strict，布尔确认字段额外要求真实 JSON boolean（含 Literal True/False）；数值不能用 true 或字符串代替。22 项 Python 测试中包含此回归。 |
| 写脚本失败留下永久未决标记 | 明确区分发送前失败与可能已发送。前者保存 not_submitted 终结收据并释放锁，旧编号仅返回该失败；后者仍保留未知状态。注入 run.csx 写入失败，确认后端调用数为 0、锁释放且后续新调用正常。 |
| 相对工作区注册了相对配置路径 | 注册前解析绝对路径；从不同目录读取该配置的路径保持一致。 |
| 发布目录可能收进私有运行配置 | 拒绝将工作区放在本合集目录内；gitignore 和 ZIP 构建器额外排除运行配置、完整 Codex 备份、连接文件及请求目录。测试确认拒绝发生在任何写入之前。 |
